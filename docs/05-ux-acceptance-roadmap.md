# 界面、验收与交付计划

版本：1.0

## 1. 体验原则

- 工作台优先：进入产品后直接开始研究，不设置宣传页。
- 规则可见：用户在运行前能够看清每一个条件和默认值。
- 证据相连：诊断结论能够一键定位到对应图表或明细。
- 状态明确：保存、校验、排队、运行和失败都有清晰反馈。
- 信息密度适中：桌面端适合连续研究，移动端适合查看状态和结果。
- 不制造确定感：预测性表达、收益承诺和夸张评级不进入界面。

## 2. 信息结构

```text
策研台
├─ 策略
│  ├─ 策略列表
│  ├─ 策略工作台
│  └─ 版本比较
├─ 回测任务
│  ├─ 全部任务
│  └─ 参数试验
├─ 数据状态
│  ├─ 可用日期
│  ├─ 指标目录
│  └─ 数据快照
└─ 设置
   ├─ 数据目录
   ├─ 默认费用
   └─ 模型设置
```

研究诊断、参数试验和报告入口在对应能力完成后再显示。个人试用版不显示成员、套餐和付款相关入口。

## 3. 页面路径

| 页面 | 路径 | 用途 |
|---|---|---|
| 策略列表 | `/strategies` | 搜索、筛选、新建和复制策略 |
| 策略工作台 | `/strategies/{id}/workspace` | 对话、规则编辑和版本保存 |
| 回测结果 | `/results/{id}` | 指标、图表、明细和诊断 |
| 版本比较 | `/comparisons/{id}` | 最多四个结果横向比较 |
| 任务列表 | `/backtests` | 查看状态、进度、失败原因和重跑 |
| 参数试验 | `/experiments/{id}` | 查看参数与结果关系；第二阶段提供 |
| 数据状态 | `/data` | 最近完整日期、快照和指标说明 |
| 报告列表 | `/reports` | 查看和生成固定报告；第二阶段提供 |
| 设置 | `/settings` | 数据目录、默认费用和模型设置 |

## 4. 全局布局

### 4.1 桌面端

```text
┌──────────┬─────────────────────────────────────────┐
│ 品牌与   │ 顶栏：数据日期 / 任务状态                  │
│ 一级导航 ├───────────────────────────┬─────────────┤
│          │ 主内容                    │ 右侧上下文   │
│ 策略     │                           │ 参数与摘要   │
│ 任务     │                           │             │
│ 数据     │                           │             │
│ 报告     │                           │             │
│ 设置     │                           │             │
└──────────┴───────────────────────────┴─────────────┘
```

- 左侧导航宽 224 像素，可折叠至 64 像素。
- 顶栏高 56 像素。
- 工作台右侧面板默认宽 320 像素，可收起。
- 内容最大宽度不做全局固定，图表和数据表优先使用可用空间。
- 1280 像素以下默认收起右侧面板，通过图标按钮打开抽屉。

### 4.2 移动端

- 底部保留策略、任务、报告三个主要入口，其他内容进入更多菜单。
- 工作台默认显示规则摘要；对话和详细表单使用顶部标签切换。
- 结果页核心指标采用两列网格，图表占满宽度。
- 大型持仓与成交表改为逐条记录，不横向压缩全部列。
- 移动端允许查看和轻量修改，但批量参数试验建议在桌面端完成。

## 5. 视觉基线

- 气质：克制、可靠、偏研究工具，不使用营销式大标题。
- 背景：中性浅灰；正文区域为白色；状态色同时配合图标和文字。
- 颜色：上涨和下跌颜色允许在设置中切换中国市场或国际习惯。
- 字体：系统中文无衬线字体；数字使用等宽数字特性。
- 卡片圆角不超过 8 像素，不在卡片内继续嵌套卡片。
- 核心指标使用平直分组布局，避免每个数字都放入独立装饰容器。
- 图表不使用立体效果，收益与基准以线型和颜色共同区分。
- 所有不熟悉的图标按钮提供悬停说明。
- 动效只用于状态过渡，持续时间 120 至 200 毫秒。

## 6. 策略列表

### 6.1 页面组成

- 标题行：页面标题、搜索框、筛选菜单、新建策略按钮。
- 筛选：标签、更新时间、最近运行状态、创建者。
- 列表列：名称、最新版本、标签、最近回测、年化收益、最大回撤、更新时间、操作。
- 年化收益和最大回撤只展示最近一次成功结果；无结果时显示短横线。
- 默认按最近修改时间倒序。

### 6.2 行操作

- 打开工作台。
- 创建副本。
- 发起回测。
- 查看版本。
- 归档。

高频操作直接显示，其他操作收进菜单。归档前二次确认，不影响已有结果和报告。

### 6.3 空状态

展示三个模板和“从想法开始”按钮，不展示产品功能说明长文。

## 7. 策略工作台

### 7.1 桌面结构

```text
┌────────────────────────────────────────────────────────────┐
│ 策略名称 / 版本 / 保存状态        规则检查    保存版本  运行 │
├──────────────────────────────────────┬─────────────────────┤
│ 对话 | 规则 | 逻辑                   │ 当前策略摘要          │
│                                      │ 时间区间              │
│ 主编辑区                             │ 比较基准              │
│                                      │ 费用方案              │
│                                      │ 预计候选与持仓         │
│                                      │ 最近检查结果          │
└──────────────────────────────────────┴─────────────────────┘
```

### 7.2 对话标签

- 底部固定输入区，支持多行文本。
- 研究助手的规则建议以字段变更摘要展示。
- 每次变更提供“应用到草案”和“放弃”两个动作。
- 应用后显示本次改变了哪些字段，不直接保存新版本。
- 规则引用以可点击的字段标签展示。

### 7.3 规则标签

采用分组表单：

1. 股票范围。
2. 可选条件。
3. 筛选条件。
4. 排序规则。
5. 持仓和行业上限。
6. 调仓日程。
7. 成交与费用。
8. 比较基准和研究区间。

表单规则：

- 字段标签旁提供口径说明。
- 数值输入明确单位，百分比以百分数形式输入和展示。
- 条件行支持拖动排序，但筛选条件本身不因顺序改变结果。
- 校验信息紧邻字段，不只在页面顶部汇总。
- 高级参数默认折叠，但摘要中仍展示其默认值。

### 7.4 逻辑标签

- 只读展示规范化后的策略协议。
- 支持复制协议文本。
- 同时提供普通语言摘要。
- 不提供任意程序代码输入框。

### 7.5 保存与运行

- 自动保存草案，用户停止输入 800 毫秒后触发。
- “保存版本”要求填写可选版本说明，并展示与上一版本差异。
- “运行”始终基于已经保存的版本；存在未保存修改时先要求保存。
- 运行前打开确认面板，列出时间区间、数据快照、费用和预计资源消耗。

## 8. 任务列表

- 顶部按状态展示数量，但不使用装饰性大卡片。
- 表格列：任务名称、策略版本、区间、创建时间、状态、进度、耗时、操作。
- 运行中任务每两秒更新一次；页面不可见时降低更新频率。
- 单击失败状态打开详情抽屉，显示用户说明、发生阶段和内部定位编号。
- 参数试验的子任务折叠显示，父行展示整体完成比例。

## 9. 结果页

### 9.1 页面顺序

1. 标题与运行信息。
2. 核心指标带。
3. 净值与回撤主图。
4. 研究诊断。
5. 收益分析。
6. 持仓与集中度。
7. 成交与费用。
8. 运行假设和数据版本。

### 9.2 核心指标带

默认显示七项：累计收益、年化收益、最大回撤、年化波动率、夏普比率、累计超额收益、年化换手率。

- 每项显示数值、名称和口径入口。
- 与上一版本比较时显示差值，但不使用“更好”或“更差”的自动评级。
- 无法计算时显示原因，不显示 0。

### 9.3 主图

- 上半部分：策略净值、比较基准和可选超额净值。
- 下半部分：回撤。
- 两图共享时间轴和缩放范围。
- 悬停同时显示同一日期的策略、基准、回撤和持仓数量。
- 用户框选日期后，页面其余分析可以切换到所选区间。

### 9.4 研究诊断

- 先展示 3 至 5 条最重要结论。
- 每条包括结论、证据引用、适用区间和限制。
- 点击证据引用滚动到对应组件并高亮相关时间范围。
- 下一步建议以可执行试验表达，例如“把持仓数从 20 改为 30 和 40 比较”，但不自动运行。

### 9.5 明细

- 收益：月度矩阵、年度表、市场阶段和个股贡献。
- 持仓：每日持仓、行业分布、前五占比和集中度。
- 成交：成交记录、未成交原因、费用拆分和换手率。
- 所有表格支持字段排序、日期筛选和 CSV 导出。
- 导出内容带结果编号、导出时间和字段说明链接。

## 10. 版本比较

### 10.1 选择规则

- 最多选择四个成功结果。
- 默认建议选择同一策略的不同版本。
- 数据快照或研究区间不同仍可比较，但必须明确标识。

### 10.2 页面内容

- 顶部固定版本名称和颜色映射。
- 参数差异表只显示有差异的字段，可展开查看全部。
- 指标表支持共同区间和各自完整区间切换。
- 净值与回撤叠加显示。
- 展示持仓重合率、行业权重差和费用差。
- 不自动宣布“最佳版本”，默认按稳定性维度解释差异。

## 11. 参数试验

- 首版一次只允许变化一个参数。
- 用户可以输入最多十个离散值，或设置起点、终点和步长。
- 运行前展示总任务数、预计时间和使用额度。
- 结果图横轴为参数值，纵轴可切换收益、回撤、夏普比率和换手率。
- 同时展示样本内与样本外结果，默认按样本外稳定性排序。
- 若相邻参数结果剧烈变化，显示“参数敏感”提示。

## 12. 数据状态页

- 显示最近完整交易日、当前快照编号和发布时间。
- 分数据类别展示覆盖起止日期、记录数、最近更新时间和质量状态。
- 指标目录支持搜索，并显示公式、单位、最短历史长度和空值规则。
- 数据修订时展示受影响日期范围，不展示供应方内部字段。

## 13. 报告

### 13.1 固定章节

1. 封面：策略名称、版本、结果编号和生成日期。
2. 策略规则摘要。
3. 数据、费用和成交假设。
4. 核心指标。
5. 净值和回撤。
6. 月度与年度表现。
7. 持仓、行业和贡献。
8. 研究诊断与限制。
9. 版本、快照和引擎信息。
10. 重要说明。

### 13.2 版式要求

- A4 纵向，图表清晰可打印。
- 页眉显示策略短名称，页脚显示页码和结果编号。
- 表格跨页时重复表头。
- 不使用网页截图拼接，报告由结构化结果直接渲染。
- 生成后进行页数、空白页、文本溢出和图表缺失检查。

## 14. 可用性要求

- 所有主要操作能够通过键盘完成。
- 焦点状态清晰可见。
- 正文和背景对比度达到 WCAG AA。
- 状态不能只依赖颜色表达。
- 图表提供同数据表格入口。
- 表单错误与字段建立程序化关联。
- 页面缩放到 200% 时核心流程仍可使用。

## 15. 事件记录

只记录产品改进所需事件，不记录用户输入全文。

| 事件 | 关键属性 |
|---|---|
| `strategy_started` | 起始方式、模板编号 |
| `strategy_spec_confirmed` | 完整耗时、补问轮数 |
| `strategy_validation_failed` | 规则编号、错误数量 |
| `backtest_started` | 区间年数、股票范围类型 |
| `backtest_finished` | 成功状态、耗时、成交数量 |
| `result_viewed` | 结果编号、查看模块 |
| `diagnosis_reference_opened` | 证据类型 |
| `version_compared` | 版本数量、区间模式 |
| `report_generated` | 页数、耗时 |

个人试用版使用不可反查的本地分析编号。产品事件只保存在本机；准备公开使用时再确定集中保存周期。

## 16. 端到端验收场景

### A01：从想法完成首次回测

前置：数据状态正常，用户没有已有策略。

1. 用户输入质量、估值和趋势组合想法。
2. 研究助手补问缺失项。
3. 系统生成完整规则草案。
4. 用户确认默认值并保存版本。
5. 规则检查通过。
6. 用户启动回测。
7. 任务成功并打开结果页。

通过条件：全流程在 15 分钟内可完成；结果存在成交、指标、图表、持仓和诊断；能够追溯所有版本编号。

### A02：财务披露时间正确

准备一条在交易日收盘后披露的财务记录。

通过条件：该记录不影响披露当日信号，只能从下一个交易日的信号开始使用。

### A03：执行日停牌

准备一只入选后连续停牌两日、第三日恢复交易的股票。

通过条件：前两日不成交，第三日按规则执行，事件记录完整。

### A04：价格限制导致未成交

准备一只执行日开盘处于不利价格边界且无法正常成交的股票。

通过条件：当日不成交，按规则顺延或取消，现金和持仓保持一致。

### A05：费用跨日期变化

研究区间跨越法定费率调整日。

通过条件：调整日前后采用各自有效费率，报告列出费用表版本。

### A06：版本差异

把持仓数量从 20 改为 30，其余字段不变并保存新版本。

通过条件：差异页只突出该字段；旧版本协议与旧结果不变化。

### A07：重复运行

使用相同策略版本、数据快照、引擎版本和研究设置连续运行三次。

通过条件：正式输出文件校验值一致。

### A08：无成交结果

设置不可能满足的筛选条件。

通过条件：任务成功结束但明确显示无成交；展示各层候选数量；收益相关指标按规范处理。

### A09：任务取消

在运行阶段取消任务。

通过条件：10 秒内停止；状态为已取消；不生成正式结果；策略版本不受影响。

### A10：诊断数字核对

生成含最大回撤、费用和行业贡献的诊断。

通过条件：每个数字均能在结果记录中找到完全一致的来源；点击引用能够定位对应组件。

### A11：移动端查看

在 390×844 尺寸打开已完成结果。

通过条件：指标、主图、诊断和明细入口均可使用，无文本遮挡和横向页面溢出。

### A12：报告生成

对十年结果生成报告。

通过条件：章节完整，无空白页、文本截断和图表缺失；页脚结果编号正确。

## 17. 测试分层

| 层级 | 重点 | 运行时机 |
|---|---|---|
| 单元测试 | 公式、费用、日期、权重和校验规则 | 每次代码变更 |
| 固定样例测试 | 逐日资产、成交和公司行为 | 每次引擎变更 |
| 组件测试 | 服务模块与数据库交互 | 每次代码变更 |
| 完整流程测试 | 从策略创建到报告 | 每日及发布前 |
| 视觉检查 | 桌面、平板、移动端和报告页面 | 每周及发布前 |
| 性能测试 | 十年标准策略、并发任务和大型明细 | 每个里程碑 |
| 数据质量测试 | 完整性、连续性和跨表一致性 | 每次快照发布 |

## 18. 完成定义

一个功能只有同时满足以下条件才算完成：

- 产品需求和交互稿已确认。
- 正常、空、加载、失败和只读状态完整。
- 服务端校验不依赖浏览器端校验。
- 自动测试覆盖主要规则和边界。
- 操作记录和运行观测已接入。
- 桌面与移动尺寸完成视觉检查。
- 用户文案、字段说明和重要说明已完成。
- 不产生未登记的计算口径或默认值。

## 19. 个人试用版交付计划

### 第 1 周：工程与数据基线

交付物：

- 可直接启动的本地工程。
- 策略协议 1.0。
- 内部样例数据和数据快照格式。
- 十个固定计算样例的输入与手算结果。

阶段门槛：本机能够打开产品，并读取固定样例数据。

### 第 2 至 3 周：可信回测核心

交付物：

- 协议校验、规范化和校验值。
- 日历、持仓、现金、成交和费用计算。
- 信号筛选、排序和权重。
- 交易状态和公司行为处理。
- 十个固定样例全部通过。

阶段门槛：固定输入连续运行三次结果一致，逐日金额与手算结果一致。

### 第 4 至 5 周：策略工作台

交付物：

- 策略列表和结构化编辑器。
- 规则检查、版本保存和差异查看。
- 任务创建、状态、取消和重新运行。
- 三个默认策略模板。

阶段门槛：可以从空白创建策略并成功运行，不需要手工修改协议文本。

### 第 6 周：结果分析

交付物：

- 核心指标、净值和回撤。
- 月度收益矩阵和年度收益。
- 持仓、成交、行业、贡献和费用明细。
- 两个版本的结果比较。

阶段门槛：A01 至 A09 验收场景全部通过。

### 第 7 至 8 周：个人试用与修正

交付物：

- 使用真实数据完成不少于十个策略研究。
- 逐项复核异常收益日期、成交和费用。
- 修正影响实际使用的问题。
- 完善本地启动、数据更新和备份流程。

阶段门槛：连续两周日常使用无阻断问题，结果复现率 100%。

### 第二阶段：核心稳定后

- 研究诊断与证据引用。
- 单参数试验。
- PDF 报告。
- 移动端完整体验。
- 更丰富的指标目录。

### 第三阶段：准备公开使用时

- 标准身份服务和成员角色。
- PostgreSQL、Redis 和对象存储迁移。
- 数据商业使用范围确认。
- 订阅、额度和付款流程。
- 小范围外部试用及公开发布准备。

第二、三阶段不设当前交付日期，以个人试用反馈决定是否进入。

## 20. 公开使用阶段团队分工参考

| 角色 | 人数 | 主要责任 |
|---|---:|---|
| 产品负责人 | 1 | 范围、验收、用户研究和交付协调 |

| 智能应用工程 | 1 | 规则补全、证据包和诊断 |

## 22. 公开使用前确认清单

以下事项不影响前 12 周开发，但必须在第 15 周前完成：

- 数据供应方、费用和书面使用范围。
- 运营主体、用户条款和隐私说明。
- 免费版、专业版和团队版最终额度。
- 支付渠道和发票流程。
- 正式运行区域、域名和服务支持方式。
- 默认无风险收益率和比较基准说明文案。

若数据使用范围未确认，产品只能继续内部试用，不能进入正式收费发布。

## 23. 公开使用后的 30 天计划

- 每日检查任务成功率、平均耗时和数据发布时间。
- 每周抽样核对十个结果的指标与成交明细。
- 第 7 天复盘首次回测漏斗。
- 第 14 天确定最常见的失败原因和规则缺口。
- 第 21 天评估参数试验、版本比较和诊断的真实使用率。
- 第 30 天决定下一版本优先级，不预先承诺 P1 的全部功能。
