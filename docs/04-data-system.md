# 数据与系统方案

版本：1.0  
目标：支撑首版日频研究，并为后续扩展保留清晰边界

## 1. 总体决策

当前实现说明：0.1 个人试用切片先使用 Node 内置服务完成零依赖启动和端到端流程验证。它是过渡实现，不改变本节确定的正式技术方向；切换 Python 服务时保持策略协议、浏览器接口和结果格式不变。

个人试用版采用单体服务加本地计算进程，不提前引入多人和公开运营所需的基础设施：

- 浏览器端：Next.js、React、TypeScript、ECharts。
- 业务服务：Python 3.12、FastAPI、Pydantic、SQLAlchemy。
- 计算层：Python、Polars、NumPy，自研受控的日频组合引擎。
- 本地任务：独立工作进程，任务状态保存到 SQLite。
- 业务数据库：SQLite，启用 WAL 模式。
- 行情与结果文件：Parquet，保存到本地数据目录。
- 查询辅助：DuckDB，只读查询 Parquet 结果。
- 运行方式：一个启动入口同时拉起页面、业务服务和计算进程。
- 运行观测：个人试用版使用结构化本地日志、任务历史和错误详情；公开使用阶段再接入 OpenTelemetry、Prometheus、Grafana 与集中式错误记录。

公开使用阶段再将 SQLite 替换为 PostgreSQL，将本地任务进程替换为 Celery 与 Redis，将文件目录替换为兼容 S3 的对象存储。领域模型、策略协议和回测结果格式保持不变。

选择依据：

- 日频横截面计算更适合列式数据和向量化处理。
- A 股交易状态和费用规则较特殊，需要可审计的受控引擎。
- 单体业务服务和本地文件更适合个人试用，减少安装与维护成本。
- 计算任务仍在独立进程运行，避免长任务影响普通页面请求。

## 3. 数据供应方案

### 3.1 原则

- 产品代码通过供应适配层读取数据，不依赖某一家供应方的原始字段名。
- 开发、试用和正式发布可以使用不同供应方，但都必须映射到同一内部模型。
- 正式发布前必须取得覆盖展示、缓存、衍生计算和报告输出的书面使用许可。
- 数据无法确认使用范围时，只能用于内部开发，不向外部用户展示。

### 3.2 选择流程

供应方评估按以下权重执行：

| 项目 | 权重 | 最低要求 |
|---|---:|---|
| 历史准确性 | 30% | 抽样核对通过率 99.99% |
| 时间信息完整性 | 20% | 财务披露和成分生效时间完整 |
| 使用范围 | 20% | 支持产品展示和衍生结果输出 |
| 更新稳定性 | 15% | 每日完整数据在约定时间内可用 |
| 成本 | 10% | 符合首年预算 |
| 技术支持 | 5% | 有问题反馈和修订通知机制 |

供应合同属于“发布前确认”事项。在供应方确定前，开发使用经过许可的内部样例数据，并通过适配层完成全部功能。

## 4. 内部数据模型

### 4.1 通用规则

- 证券使用内部稳定编号 `instrument_id`，不直接用交易代码作为主键。
- 日期使用 `date`，时刻使用带时区的 `timestamp`。
- 金额统一使用人民币元，数据库使用定点数。
- 比率在存储层使用小数，如 10% 保存为 `0.10`。
- 原始记录保留来源编号、接收批次和源更新时间。
- 任何修订都新增版本，不覆盖历史快照。

## 5. 数据处理流程

### 5.1 每日流程

1. 接收供应方增量文件或接口结果。
2. 保存原始批次，不做原地改写。
3. 完成格式、主键、范围、连续性和跨表一致性检查。
4. 映射到内部模型并写入待发布区域。
5. 与前一日数据量和关键统计做差异检查。
6. 达到质量门槛后生成新的数据快照。
7. 更新“最近完整交易日”，供回测任务选择。

### 5.2 数据快照

每个快照包含：

- 快照编号。
- 各数据集版本和文件清单。
- 每个文件的 SHA-256 校验值。
- 覆盖日期、证券数量和记录数量。
- 质量检查结果。
- 创建时间和发布状态。

回测任务创建后固定引用一个快照。新快照发布不改变正在运行或已经完成的任务。

### 5.3 质量门槛

阻止快照发布的情况：

- 交易日历与行情日期不一致。
- 日行情主键重复。
- 开高低收关系不成立。
- 成交量或成交额为负数。
- 大面积缺少开盘价或收盘价。
- 财务记录缺少报告期或披露时间。
- 指数成分出现重叠生效区间。
- 公司行为关键日期关系不成立。

差异提示但不一定阻止发布的情况：

- 当日证券数量较过去 20 日均值变化超过 2%。
- 单一供应批次的修订记录异常增多。
- 指数成分数量偏离预期范围。

## 6. 指标目录

每个指标必须登记：

- 稳定字段编号。
- 中文名称和说明。
- 数据类型和单位。
- 输入字段。
- 计算公式。
- 所需最短历史长度。
- 更新时间。
- 空值规则。
- 可用于筛选、排序或展示的范围。
- 指标版本。

首版指标：

| 类别 | 指标 |
|---|---|
| 估值 | 市盈率 TTM、市净率、市销率 TTM、股息率 |
| 盈利 | 净资产收益率 TTM、资产收益率 TTM、毛利率、净利率 |
| 成长 | 营收同比、净利润同比、近三年营收复合增速 |
| 质量 | 经营现金流与净利润比、资产负债率、应收款占比 |
| 表现 | 20、60、120、250 日收益，跳过最近 20 日的 120 日收益 |
| 波动 | 20、60、120 日年化波动率，60 日最大回撤 |
| 流动性 | 20 日平均成交额、20 日平均换手率 |
| 规模 | 总市值、流通市值 |

所有滚动指标使用截至信号日的可用数据，样本不足时返回空值。

## 7. 系统模块

```text
浏览器端
  ├─ 策略工作台
  ├─ 回测结果与比较
  └─ 报告与设置
        │
业务服务
  ├─ 策略与版本
  ├─ 规则校验
  ├─ 任务编排
  ├─ 结果查询
  ├─ 研究诊断
  └─ 报告生成
        │
任务队列 ── 计算工作进程 ── 回测引擎
        │                    │
PostgreSQL            Parquet / 对象存储
        │                    │
        └──────── 数据适配与快照发布
```

### 7.1 浏览器端

- 只负责交互和展示，不重新计算正式指标。
- 所有日期、金额和百分比使用统一格式化组件。
- 长任务通过服务端事件流接收进度，断线后可以重新连接。
- 表格查询由服务端分页，图表使用经过抽样但保留极值的数据。

### 7.2 业务服务

首版保留一个部署单元，内部按领域分模块：

| 模块 | 职责 |
|---|---|
| 策略 | 创建、版本、复制、标签和差异 |
| 协议 | 字段校验、默认值、升级和可读摘要 |
| 任务 | 创建、去重、排队、取消和进度 |
| 结果 | 指标、图表、明细和比较 |
| 诊断 | 证据整理、模型输入、引用核对和输出保存 |
| 报告 | 固定模板渲染和文件保存 |
| 数据 | 快照状态、字段目录和可用日期 |
| 订阅 | 套餐状态、额度发放、用量记账和方案变更；后续启用 |

### 7.3 计算工作进程

- 每个任务在独立进程中运行。
- 任务只能读取指定的数据快照。
- 任务定期写入阶段进度，不写未完成的正式结果。
- 完成后先校验输出，再一次性标记成功。
- 取消标记每个主要阶段都要检查，最长 10 秒内停止。

## 9. 服务接口

首版接口按 `/v1` 管理版本，主要资源如下：

| 方法与路径 | 用途 |
|---|---|
| `POST /v1/strategies` | 创建策略 |
| `GET /v1/strategies` | 查询策略列表 |
| `POST /v1/strategies/{id}/versions` | 保存新版本 |
| `POST /v1/strategy-spec/validate` | 校验规则草案 |
| `POST /v1/backtests` | 创建回测任务 |
| `GET /v1/backtests/{id}` | 获取任务状态 |
| `POST /v1/backtests/{id}/cancel` | 取消任务 |
| `GET /v1/results/{id}/summary` | 获取结果摘要 |
| `GET /v1/results/{id}/series` | 获取图表序列 |
| `GET /v1/results/{id}/holdings` | 分页获取持仓 |
| `GET /v1/results/{id}/trades` | 分页获取成交 |
| `POST /v1/comparisons` | 创建结果比较视图 |
| `POST /v1/results/{id}/diagnoses` | 生成研究诊断 |
| `POST /v1/reports` | 生成报告 |
| `GET /v1/data/status` | 获取数据状态 |
| `GET /v1/subscription` | 获取套餐、周期和剩余额度；后续提供 |
| `POST /v1/subscription/change` | 提交方案变更；后续提供 |

创建任务和报告的接口必须支持请求去重。同一个用户、同一个去重编号和同一请求正文只产生一个资源。

个人试用版不做额度判断。公开使用阶段增加额度后，额度扣减必须与任务创建处于同一个数据库事务；平台内部原因导致任务失败时，通过新的额度返还记录冲正，不修改原始记账记录。

## 10. 任务状态机

```text
created -> validating -> queued -> running -> finalizing -> succeeded
    │          │           │         │            │
    └──────────┴───────────┴─────────┴────────────┴-> failed
                           │         │
                           └─────────┴-> cancelling -> cancelled
```

规则：

- 只有 `succeeded` 状态可以成为正式结果。
- `failed` 必须包含用户说明和内部定位编号。
- `cancelled` 不保留临时输出文件。
- 工作进程失联后，任务先进入恢复检查；确认无法继续后再标记失败。
- 状态转换采用数据库事务，避免重复完成。

## 11. 研究助手边界

研究助手不直接操作数据文件和计算引擎，只能通过受控工具完成：

- 获取指标目录和字段说明。
- 创建或修改策略协议草案。
- 请求规则校验。
- 读取已经完成的结果摘要和证据片段。
- 生成带引用的诊断草案。

所有模型输出先经过结构校验，再进入业务流程。协议草案必须由用户确认后才能保存为版本；诊断中的数字必须与结果记录逐项核对后才能展示。

## 12. 诊断证据包

为减少模型输入量并保证结论可核对，服务端先生成证据包：

- 策略规则摘要。
- 核心指标及其口径编号。
- 最好和最差的五个自然月。
- 最大回撤区间。
- 前十个股和行业贡献。
- 持仓集中度时间序列摘要。
- 费用及换手摘要。
- 样本内与样本外对比。
- 市场阶段分段结果。

模型只能引用证据包中的数字。输出使用固定结构：结论、证据编号、适用区间、限制、下一步建议。

## 14. 非功能要求

### 14.1 性能

- 普通页面首个可用内容在良好网络下 2.5 秒内出现。
- 策略列表和任务列表查询的服务端 95 分位响应低于 500 毫秒。
- 十年、全市场、月度调整的标准策略在 4 核 8GB 计算配置下 60 秒内完成。
- 单个结果支持至少 500 万条持仓与成交明细，采用分页查询。

### 14.2 可用性

- 月度服务可用性目标 99.5%。
- 业务数据库每日完整备份，连续保留 30 天。
- 数据快照和正式结果文件启用版本保留。
- 服务恢复目标为 4 小时，业务数据恢复点目标为 24 小时。

### 14.3 数据保护

- 传输和存储均使用加密措施。
- 公开使用阶段的工作区数据按成员角色隔离。
- 模型输入只包含完成任务所需的最小数据，不包含用户联系方式等无关信息。
- 关键操作记录保存至少一年。
- 用户移除工作区后，正式数据在 30 天内清理，备份按保留周期自然到期。
